🏛️

Traffy Fondue เป็นเพียงแพลตฟอร์มผู้ให้บริการระบบเท่านั้น

แพลตฟอร์ม Traffy Fondue และผู้พัฒนาระบบ (สวทช.) ทำหน้าที่เป็นระบบเทคโนโลยีสารสนเทศตัวกลาง (Platform Service Provider) เพื่ออำนวยความสะดวกในการรับส่งและประสานงานข้อมูลระหว่างประชาชน หน่วยงานผู้รับผิดชอบ และผู้พัฒนาระบบภายนอกเท่านั้น มิได้มีฐานะเป็นผู้ผลิต สร้างสรรค์ ควบคุม ตรวจสอบ หรือรับรองความถูกต้องของเนื้อหา ข้อมูล ข้อความ ภาพถ่าย หรือพิกัดสถานที่ใดๆ ในระบบ

⚖️

ขอบเขตความรับผิดชอบต่อเนื้อหาทางกฎหมาย

ความรับผิดชอบตามกฎหมายทั้งหมดเกี่ยวกับข้อมูล ข้อความ รูปภาพ พิกัด หรือเอกสารแนบ จะตกอยู่แก่บุคคลและหน่วยงานดังต่อไปนี้โดยตรง:

  • เจ้าของเรื่องแจ้ง: รับผิดชอบต่อข้อเท็จจริง ข้อความ รูปภาพ/วีดีโอ/ไฟล์ ที่นำเข้าสู่ระบบ
  • เจ้าหน้าที่และหน่วยงานผู้รับผิดชอบ: รับผิดชอบต่อข้อความ รูปภาพ/วีดีโอ/ไฟล์ ที่ใช้อัปเดตสถานะการดำเนินงาน
  • ผู้นำข้อมูลไปใช้ต่อ: รับผิดชอบต่อการจัดเก็บ ประมวลผล และการนำข้อมูลไปใช้งานหรือเผยแพร่ต่อ

หากเกิดข้อพิพาท การละเมิดสิทธิ หรือการฟ้องร้องดำเนินคดีใดๆ ผู้พัฒนาและผู้ให้บริการแพลตฟอร์ม Traffy Fondue ขอปฏิเสธความรับผิด (Disclaimer of Liability) ในทุกกรณี

🚨

คำเตือนสำคัญสำหรับผู้ใช้งานผ่านระบบ Exchange API

ข้อมูลเรื่องแจ้ง รายละเอียด ข้อความ และรูปภาพที่ได้รับผ่าน Exchange API เป็น "ข้อมูลดิบ (Raw Data)" ที่ ไม่ผ่านการคัดกรองหรือเซนเซอร์ใดๆ (Uncensored)

⚠️ ข้อปฏิบัติที่ต้องระมัดระวังสูงสุด:
  • ระวังการเผยแพร่ข้อมูลออกสู่สาธารณะให้มากที่สุด: การดึงข้อมูลไปเพื่อวิเคราะห์ แสดงผล หรือพัฒนาบริการ ต้องกระทำด้วยความระมัดระวังรอบคอบ
  • ปฏิบัติตามกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA) อย่างเคร่งครัด: ข้อมูลดิบอาจมีข้อมูลส่วนบุคคล เช่น ภาพถ่ายใบหน้าบุคคล ป้ายทะเบียนรถ หมายเลขบัตรประชาชน เบอร์โทรศัพท์ หรือพิกัดบ้านพักอาศัย
  • ต้องทำ Data Masking / Redaction ก่อนเผยแพร่: หากมีการนำข้อมูลไปแสดงผลต่อสาธารณะ ต้องเบลอภาพ เซนเซอร์ หรือตัดทอนข้อมูลส่วนบุคคลออก มิฉะนั้นอาจมีความผิดตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล และ พ.ร.บ. ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์

การยืนยันตัวตน (Authentication)

แลกเปลี่ยน Username และ Password ที่ได้รับจากทีมงานเพื่อรับ JWT Bearer Token

1. /get-auth ขอ JWT Bearer Token
POST https://publicapi.traffy.in.th/exchange-api/get-auth/v1 🔑 Auth: User / Pass

นำ user และ pass ที่ได้รับทาง Email มาแลกรับ JWT (JSON Web Token) เพื่อใช้เป็น Header Authorization: Bearer <token> ยืนยันตัวตนใน API อื่นๆ เกือบทั้งหมด

  • ห้ามเผยแพร่ user และ pass สู่สาธารณะเด็ดขาด เช่น ห้ามฝังไว้ในเว็บไซต์หรือ mobile app เพราะอาจถูก inspect หรือ sniffing ดูได้ — ให้ขอ token จาก server เท่านั้น
  • หาก credit_balance ลดลงเร็วผิดปกติ ให้รีบติดต่อทีมงาน Traffy ทันที ที่ LINE @fonduehelp เพื่อตรวจสอบและเปลี่ยนรหัสใหม่
  • JWT token ถูกตั้งเวลาให้หมดอายุ โปรดตรวจสอบจาก expire_timestamp ที่ได้รับมาพร้อมกับ token
Request Body (JSON)
ชื่อ คำอธิบาย ตัวอย่าง REQUIRED?
userstring ชื่อผู้ใช้งานของ account ที่ได้รับแจ้งในเอกสารการใช้งาน — ห้ามเผยแพร่สู่สาธารณะเด็ดขาด YOUR_USERNAME REQUIRED
passstring รหัสผ่านของ account ที่ได้รับแจ้งในเอกสารการใช้งาน — ห้ามเผยแพร่สู่สาธารณะเด็ดขาด YOUR_PASSWORD REQUIRED

การขอข้อมูลจาก Fondue (Data Retrieval)

API สำหรับดึงรายการเรื่องแจ้ง ประวัติ ข้อมูลสถิติ และผังโครงสร้างหน่วยงาน

⚠️
ข้อควรระวังเรื่องการเผยแพร่ข้อมูลสู่สาธารณะ: ข้อมูลเรื่องแจ้ง ข้อความ และรูปภาพที่ส่งไป เป็นข้อมูลดิบที่ไม่ผ่านการเซนเซอร์ (Uncensored) ให้ระวังการเผยแพร่ข้อมูลออกสู่สาธารณะให้มากที่สุด และต้องปฏิบัติตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA) โดยทำการเบลอหรือเซนเซอร์ข้อมูลส่วนบุคคล ก่อนเผยแพร่สู่สาธารณะ
2. /get-issues ขอรายการเรื่องแจ้ง
GET https://publicapi.traffy.in.th/exchange-api/get-issues/v2 🛡️ Header: Bearer Token

ระบบ Traffy Fondue ส่งข้อมูลการอัปเดตสถานะ บันทึกการปฏิบัติงาน และภาพถ่ายผลงาน แบบ HTTP PATCH ทันทีที่มีการเปลี่ยนสถานะ

หมายเหตุ: ห้ามส่งการอัปเดตที่ได้รับมาจาก Traffy Fondue webhook วนกลับมาที่ API update-issue เพื่อป้องกันการเกิด loop

Incoming Payload (JSON)
Field Type คำอธิบาย
event string ประเภทของข้อความ
ticket_id string หมายเลขเรื่องแจ้ง Fondue
status string สถานะที่อัปเดต เช่น เสร็จสิ้น
note string คำอธิบายประกอบการอัปเดต
photo array[str] ภาพถ่ายหลังการแก้ไข (ถ้าไม่มีการแนบรูป จะเป็น null)
tl_org_id integer หมายเลขหน่วยงานผู้ดำเนินการ
tl_org string ชื่อหน่วยงานผู้ดำเนินการ
tl_status string สถานะที่ถูกบันทึกลง time line (รวมถึง "ติดตามเรื่อง" และ "ส่งต่อ" ด้วย)

16. Webhook รับความคิดเห็นและแชท (เมื่อมีการแสดงความคิดเห็นหรือแชท)
POST (Webhook) Client Webhook URL ⚡ Non-Quota

ระบบ Traffy Fondue ส่งข้อมูลความคิดเห็น แชท หรือการให้คะแนนแบบ HTTP POST ทันทีที่มีเหตุการณ์เกิดขึ้น

หมายเหตุ: ห้ามส่งการแสดงความคิดเห็นที่ได้รับมาจาก Traffy Fondue webhook วนกลับมาที่ API messagecomment เพื่อป้องกันการเกิด loop

Incoming Payload (JSON)
Field Type คำอธิบาย
event string ประเภทของเหตุการณ์ เช่น chat, rating, comment, chat_staff_only
message_comment_id integer รหัสความคิดเห็นในระบบ
message_id integer รหัสข้อความในระบบ
ticket_id string หมายเลขเรื่องแจ้ง Fondue
comment string ข้อความแสดงความคิดเห็น
timestamp string วันเวลาที่มีการแสดงความคิดเห็น
sender_org_id integer รหัสหน่วยงานผู้ส่ง (ถ้ามี)
sender_org string ชื่อหน่วยงานผู้ส่ง (ถ้ามี)
sender_user_id integer รหัสผู้ใช้งานผู้ส่ง
sender_username string ชื่อผู้ใช้งานผู้ส่ง

Error Message สาเหตุ แนวทางแก้ไข
